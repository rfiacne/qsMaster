# Feature Specification: 标准答案管理与人工审核工作流 (M3)

**Feature Branch**: `003-standard-answers-review`
**Created**: 2026-06-09
**Status**: Draft
**Input**: M3 标准答案管理 + 人工审核工作流

## Background

M1 建立了核心 RAG 管道（文档导入 → turbovec 向量检索 → 单轮问答 → 引用溯源），M2 在此基础上增加了混合检索（PG 全文检索 + Reranker 精排）、Early Exit（标准答案直接返回）和 Faithfulness Evaluator 防幻觉。

M2 的 Early Exit 已引入标准答案概念，但标准答案的创建和维护仍为手动脚本操作，缺乏系统化管理；Faithfulness Evaluator 未通过的回答仅记录日志，缺少人工介入闭环。

M3 填补这两个缺口：

1. **标准答案库系统化管理**——业务专家可对标准问答对执行增删改查、启用禁用、分类标签等操作，使标准答案成为可运营的知识资产而非静态配置。
2. **人工审核闭环**——系统生成的回答（特别是 Evaluator 未通过的）自动进入审核队列，业务专家通过 CLI 标注审核意见，标注结果反馈到标准答案候选池和检索策略改进。

> 后续里程碑：M4 多轮对话 + OpenTelemetry 可观测性、M5 Web 前端 + API 网关。每个里程碑独立创建 spec。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 标准答案生命周期管理 (Priority: P1)

业务专家通过 CLI 创建、编辑、禁用、删除标准问答对。每个标准答案包含问题文本、标准回答、关联文档片段、生效日期、过期标记、分类标签。被禁用的标准答案不参与 Early Exit 匹配但保留历史记录。

**Why this priority**: 标准答案是 M2 Early Exit 的运营基础。没有 CRUD 管理能力，标准答案库无法持续维护，Early Exit 形同虚设。

**Independent Test**: 创建一条标准答案 → 验证 Early Exit 命中 → 编辑回答内容 → 验证更新生效 → 禁用 → 验证不再命中 → 重新启用 → 验证恢复命中。

**Acceptance Scenarios**:

1. **Given** 系统中无任何标准答案, **When** 业务专家通过 CLI 创建一条标准答案（含问题文本、标准回答、分类标签、生效日期）, **Then** 该标准答案立即可被 Early Exit 路由匹配到，返回标准回答。
2. **Given** 一条已生效的标准答案, **When** 业务专家将其标记为禁用, **Then** 该标准答案不再被 Early Exit 命中，但可通过查询历史记录找到。
3. **Given** 一条标准答案的关联文档片段已过期或被删除, **When** 业务专家更新其关联片段至新版本, **Then** 标准答案引用来源更新为新版本，且引用溯源功能正常工作。

---

### User Story 2 - 语义匹配与别名问题入库 (Priority: P1)

用户问答对经人工审核标注为"正确"后，系统自动计算该问题与现有标准答案的语义相似度。若相似度低于配置阈值，则创建新的标准答案候选；若相似度达到阈值，则将该问题添加为已有标准答案的别名问题。别名问题与原始问题共享标准回答，命中任一别名即触发 Early Exit。

**Why this priority**: 语义匹配是标准答案库持续扩展的核心机制，也是连接审核工作流与 Early Exit 的桥梁。没有自动入库，标准答案只能手动逐条维护，无法规模化。

**Independent Test**: 标注一条审核为"正确"的新问题 → 若与现有标准答案相似度低于阈值 → 验证新候选创建；若高于阈值 → 验证别名添加生效。

**Acceptance Scenarios**:

1. **Given** 审核队列中一条标注为"正确"的问答对，且与所有现有标准答案的语义相似度均低于阈值, **When** 系统自动处理该审核结果, **Then** 该问答对进入标准答案候选池，等待达到配置的确认数量阈值后正式入库。
2. **Given** 审核队列中一条标注为"正确"的问答对，且与某条现有标准答案的语义相似度达到阈值, **When** 系统自动处理该审核结果, **Then** 该问题被添加为该标准答案的别名问题，查询该别名时可触发 Early Exit 返回标准回答。
3. **Given** 一条标准答案已有 3 个别名问题, **When** 业务专家查看该标准答案详情, **Then** 系统展示所有别名问题列表及其语义相似度分数。

---

### User Story 3 - 人工审核工作流 (Priority: P1)

系统生成的回答（特别是 Faithfulness Evaluator 未通过的）自动进入审核队列。业务专家通过 CLI 浏览审核队列，对每条问答标注"正确/部分正确/错误"，并可添加修正意见。标注为"正确"的问答自动进入标准答案候选池；标注为"错误"的问答用于改进检索策略（记录反馈但不直接入库）。

**Why this priority**: 审核工作流是 M2 Faithfulness Evaluator 的必要闭环——未能通过自动评估的回答需要人工介入判定，审核结果反哺标准答案库和检索策略，形成质量改进飞轮。

**Independent Test**: 触发一条 faithfulness 评估未通过的问答 → 验证出现在审核队列 → 标注为"错误"并添加修正意见 → 验证状态变更和记录 → 标注为"正确" → 验证进入标准答案候选池。

**Acceptance Scenarios**:

1. **Given** Faithfulness Evaluator 对某条问答评估为"未通过", **When** 评估结果生成, **Then** 该问答自动进入审核队列，包含原始问题、系统回答、引用来源、评估分数和评估理由。
2. **Given** 审核队列中有待审核项, **When** 业务专家通过 CLI 查看待审核列表, **Then** 系统按优先级排序（Evaluator 未通过优先于正常问答）展示待审核项，每项显示问题摘要、回答摘要、评估状态。
3. **Given** 业务专家审核一条问答, **When** 标注为"正确", **Then** 问答自动进入标准答案候选池，并触发语义匹配流程（US2）。**When** 标注为"错误"并添加修正意见, **Then** 问答状态标记为"已审核-错误"，修正意见归档用于检索策略改进分析，该问答不入标准答案库。

---

### User Story 4 - 审核统计报表 (Priority: P2)

业务专家通过 CLI 查看审核相关统计：标注完成率、标准答案覆盖率、准确率趋势等基本统计指标，用于评估知识库质量和审核工作效率。

**Why this priority**: 统计报表是质量运营的辅助工具，支持决策但不阻塞核心流程。P1 先保证 CRUD 和审核闭环可用，P2 再增加可观测性。

**Independent Test**: 完成若干审核操作后，通过 CLI 查看报表 → 验证数据与实际操作一致。

**Acceptance Scenarios**:

1. **Given** 系统中有 100 条审核项，其中 60 条已完成审核, **When** 业务专家查看标注完成率, **Then** 系统显示完成率为 60%，并按正确/部分正确/错误分类统计。
2. **Given** 知识库覆盖 10 个业务类别，其中 7 个类别有标准答案, **When** 业务专家查看标准答案覆盖率, **Then** 系统显示覆盖率 70%，并列出缺少标准答案的类别。
3. **Given** 过去 7 天审核了 50 条问答, **When** 业务专家查看准确率趋势, **Then** 系统按日展示"正确"比例趋势和 Faithfulness Evaluator 分数趋势。

---

### Edge Cases

- 标准答案的问题文本与某文档片段完全相同，系统应将其关联而非重复创建。
- 审核队列中同一条问答被两个业务专家同时审核时，系统应防止重复标注冲突（首次标注生效）。
- 语义匹配阈值配置为极值（0.0 或 1.0）时，系统应给出参数无效警告并拒绝设置。
- 一条标准答案被禁用后，其所有别名问题应同步禁用；重新启用时也应同步恢复。
- 审核队列项超过配置的最大保留时间（如 90 天）仍未审核时，系统应自动归档并通知管理员。

## Requirements *(mandatory)*

### Functional Requirements

**标准答案管理**

- **FR-001**: 系统 MUST 提供标准答案的创建功能，每条标准答案包含：问题文本、标准回答、关联文档片段引用、生效日期、分类标签。
- **FR-002**: 系统 MUST 提供标准答案的编辑功能，支持修改问题文本、标准回答、关联文档片段、分类标签。
- **FR-003**: 系统 MUST 提供标准答案的禁用/启用功能，禁用后该标准答案及其所有别名问题不参与 Early Exit 匹配，但保留历史记录和审计追踪。
- **FR-004**: 系统 MUST 提供标准答案的删除功能，删除前必须确认该标准答案无活跃的审核关联（或强制级联删除）。
- **FR-005**: 系统 MUST 支持按分类标签、生效日期、状态（启用/禁用）对标准答案进行列表查询和筛选。
- **FR-006**: 系统 MUST 为每条标准答案维护别名问题列表，别名与原始问题共享标准回答，命中任一别名均触发 Early Exit。

**语义匹配入库**

- **FR-007**: 系统 MUST 在问答对被标注为"正确"后，自动计算该问题与所有现有标准答案的语义相似度。
- **FR-008**: 系统 MUST 根据可配置的相似度阈值决定：低于阈值则创建标准答案候选，达到阈值则添加为别名问题。
- **FR-009**: 系统 MUST 记录每条标准答案与别名问题之间的相似度分数，并可在查看详情时展示。
- **FR-010**: 系统 MUST 维护标准答案候选池，候选达到可配置的确认数量阈值后自动转正为正式标准答案。

**审核工作流**

- **FR-011**: 系统 MUST 将 Faithfulness Evaluator 评估为"未通过"的问答自动加入审核队列，包含原始问题、系统回答、引用来源、评估分数及理由。
- **FR-012**: 系统 MUST 支持业务专家通过 CLI 浏览审核队列，按优先级排序展示待审核项（Evaluator 未通过优先）。
- **FR-013**: 系统 MUST 支持业务专家对审核项进行三级标注："正确"、"部分正确"、"错误"，并可附加修正意见文本。
- **FR-014**: 系统 MUST 将标注为"正确"的问答自动推入标准答案候选池（触发 FR-007）。
- **FR-015**: 系统 MUST 将标注为"错误"的问答归档并记录修正意见，用于检索策略改进分析，但不进入标准答案库。
- **FR-016**: 系统 MUST 防止同一条审核项被重复标注（首次标注生效，后续标注记录为历史但不覆盖结果）。
- **FR-017**: 系统 MUST 对超过可配置保留期限仍未审核的队列项自动归档，并生成归档通知。

**审核统计**

- **FR-018**: 系统 MUST 提供标注完成率统计：已审核数 / 总队列数，按"正确/部分正确/错误"分类。
- **FR-019**: 系统 MUST 提供标准答案覆盖率统计：已有标准答案的业务类别数 / 总类别数。
- **FR-020**: 系统 MUST 提供准确率趋势统计：按日/周展示"正确"比例趋势和 Faithfulness Evaluator 分数趋势。

**接口与安全**

- **FR-021**: 系统 MUST 通过 CLI 命令提供标准答案管理、审核操作、统计查询的所有功能。
- **FR-022**: 系统 MUST 对所有标准答案的创建、编辑、禁用、删除操作记录操作人、时间、变更内容（审计追踪）。
- **FR-023**: 系统 MUST 对所有 CLI 命令的输入参数进行验证，拒绝非法输入并给出明确错误信息。

### Key Entities

- **StandardAnswer**: 标准问答对。属性：问题文本、标准回答、关联文档片段引用列表、别名问题列表、分类标签、状态（启用/禁用/候选）、生效日期、过期标记、创建信息（操作人/时间）、更新信息（操作人/时间/变更内容）。
- **AliasQuestion**: 标准答案的别名问题。属性：问题文本、语义相似度分数、所属标准答案 ID、创建时间。
- **ReviewItem**: 审核队列项。属性：原始问题、系统回答、引用来源、Faithfulness 评估分数、评估理由、审核状态（待审核/已审核-正确/已审核-部分正确/已审核-错误）、审核人、审核时间、修正意见、优先级标记、入队时间。
- **ReviewStatistics**: 审核统计快照。属性：标注完成率、分类统计（正确/部分正确/错误各多少）、标准答案覆盖率、准确率趋势数据点、快照时间。
- **AuditLog**: 操作审计记录。属性：操作类型（创建/编辑/禁用/启用/删除）、操作目标（标准答案 ID）、变更前内容、变更后内容、操作人、操作时间。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 标准答案 CRUD 全链路功能可用——创建、编辑、禁用、启用、删除操作均通过端到端验收测试。
- **SC-002**: Early Exit 命中别名问题时返回与原始标准答案相同的回答，成功率 100%。
- **SC-003**: 语义匹配阈值在默认配置下，别名问题归属准确率 ≥ 85%（人工评估 50 个问答对）。
- **SC-004**: Faithfulness Evaluator 未通过的问答 100% 自动进入审核队列，无遗漏。
- **SC-005**: 审核标注操作正确触发后续流程——"正确"标注进入候选池、"错误"标注归档记录——准确率 100%。
- **SC-006**: 审核队列操作（浏览、标注、查询）CLI 响应时间 p95 < 2 秒。
- **SC-007**: 审核统计报表数据与实际操作记录一致，误差率 0%。
- **SC-008**: 标准答案操作审计追踪 100% 记录，无遗漏任何创建/编辑/禁用/删除操作。

## Assumptions

- M2 的 Early Exit 机制和 Faithfulness Evaluator 已实现且稳定可用，M3 在此基础上扩展。
- M2 的 PostgreSQL 实例已部署且可扩展新表，标准答案库、审核队列、审计日志均存储在 PG 中。
- M3 的 CLI 交互模式与 M1/M2 保持一致，复用既有 CLI 框架。
- 业务专家为唯一审核角色，M3 阶段不实现多角色权限（审核员/管理员等）。
- 语义匹配复用 M1/M2 的 turbovec 向量检索能力，不引入新的嵌入模型。
- 标准答案库初始为空，通过审核工作流和手动创建逐步积累。
- 候选池确认阈值默认为 1（单次"正确"标注即可入库），可通过配置调整。
- 审核队列项的保留期限默认 90 天，超过后自动归档。
- M3 仅 CLI 交互，Web 审核界面在 M5 实现。
- 标准答案的"部分正确"标注仅归档记录，不进入候选池，不触发语义匹配入库。
- 语义相似度阈值默认值在实现阶段确定，但必须可通过配置修改，边界值（0.0 和 1.0）应被拒绝。
- 审核和标准答案管理功能仅面向授权的业务专家，M3 阶段通过简单身份标识（如 CLI 配置的用户名）实现，不在 M3 实现完整 RBAC。
