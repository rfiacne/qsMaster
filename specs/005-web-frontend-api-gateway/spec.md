# Feature Specification: Web 前端 + API 网关 (M5)

**Feature Branch**: `005-web-frontend-api-gateway`
**Created**: 2026-06-09
**Status**: Draft
**Input**: M5 Web 前端 + API 网关 + RBAC

## Background

M1-M4 已建立完整 RAG 内核：

- **M1**：核心问答闭环（文档导入 → turbovec 向量检索 → 单轮问答 → 引用溯源）
- **M2**：混合检索（PG 全文检索 + Reranker 精排）+ Early Exit + Faithfulness Evaluator
- **M3**：标准答案管理 + 人工审核工作流
- **M4**：多轮对话 + 审计日志 + OpenTelemetry 可观测性

上述能力均通过 CLI 或内部 API 暴露，尚无面向终端用户的交互界面，也无标准化的外部 API 入口。M5 是最终交付里程碑，补齐两个关键缺口：

1. **用户交互层**：业务人员、业务专家、管理员需要一个 Web 界面完成问答、文档管理、标准答案管理、审核标注和使用统计
2. **API 网关层**：为后续 OA 系统集成提供标准化 RESTful API，统一认证、鉴权和接口规范

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 证券从业者知识问答 (Priority: P1)

证券行业从业人员通过 Web 界面输入自然语言问题，系统以打字机效果流式输出回答，引用来源以标注形式嵌入回答并可点击跳转原文。用户可在同一会话中追问，系统保留上下文（基于 M4 多轮对话能力）。

**Why this priority**: 问答是系统核心价值，Web 界面是让 M1-M4 能力触达终端用户的必要条件。没有它，前 4 个里程碑只是后端基础设施。

**Independent Test**: 登录普通用户账号，输入"沪深交易所 T+1 清算流程是什么？"，验证流式回答展示、引用标注渲染、会话历史保留。

**Acceptance Scenarios**:

1. **Given** 用户已登录, **When** 输入问题并提交, **Then** 回答以流式逐字展示（打字机效果），引用标注在回答中出现，每条引用可展开查看原文片段。
2. **Given** 用户在一个会话中已有问答历史, **When** 继续追问, **Then** 系统基于会话上下文生成回答，历史问答记录保留在同一会话视图。
3. **Given** 用户提问触发 M2 Early Exit（命中标准答案）, **When** 系统返回标准答案, **Then** 回答标注"标准答案"标签，不出现流式生成效果（即时展示）。

---

### User Story 2 - 管理员文档与知识库管理 (Priority: P1)

管理员通过 Web 界面上传、删除文档，查看索引构建状态（排队中/处理中/完成/失败），对文档进行批量操作（添加分类标签、批量删除）。

**Why this priority**: 知识库是问答系统的数据基础，管理员必须能通过 Web 界面维护文档。CLI 管理方式无法推广到非技术用户。

**Independent Test**: 登录管理员账号，上传一份 PDF 文件，验证状态从"排队中"变为"完成"，检查知识库搜索命中该文档。

**Acceptance Scenarios**:

1. **Given** 管理员已登录, **When** 上传一份 PDF 文件并填写元数据（来源、类别、版本）, **Then** 文档进入索引队列，状态实时更新，完成后可在知识库中检索到。
2. **Given** 知识库中有多份文档, **When** 管理员选中 3 份文档批量删除, **Then** 文档从知识库移除，关联的检索结果不再出现。
3. **Given** 索引构建过程中, **When** 某文档解析失败, **Then** 状态标记为"失败"并展示错误信息，不阻塞其余文档的索引流程。

---

### User Story 3 - 业务专家标准答案管理与审核 (Priority: P2)

业务专家通过 Web 界面创建、编辑标准问答对（含别名和有效期），并在审核队列中对 M2 Early Exit 触发的候选问答对进行审核标注（确认/驳回/修改后确认）。管理员可查看审核统计看板。

**Why this priority**: 标准答案是提升回答精准度的关键机制（M2 Early Exit 依赖它），但管理后台是 M3 已有能力的 Web 化呈现。P2 因为标准答案和审核工作流在 M3 已验证 CLI 流程，Web 界面是锦上添花。

**Independent Test**: 登录业务专家账号，创建一条标准问答对，验证搜索命中；在审核队列中标注一条候选问答，验证统计看板数据更新。

**Acceptance Scenarios**:

1. **Given** 业务专家已登录, **When** 创建一条标准问答对（问题、答案、别名列表、有效期）, **Then** 问答对保存成功，别名可搜索命中，有效期状态正确标记。
2. **Given** 审核队列中有 M2 产生的候选问答对, **When** 业务专家标注一条为"确认", **Then** 该问答对变为正式标准答案，审核队列中移除。
3. **Given** 业务专家标注一条候选为"驳回"并填写原因, **When** 提交后, **Then** 该候选标记为已驳回，不再出现在审核队列默认视图中（可筛选查看）。

---

### User Story 4 - 使用统计与系统洞察 (Priority: P2)

管理员和业务专家通过使用统计页面查看问答量趋势、准确率趋势、热门问题排名，用于评估系统价值和发现知识库缺口。

**Why this priority**: 统计功能帮助运营决策，但不影响核心问答流程。M5 交付优先完成问答和管理，统计作为增值功能。

**Independent Test**: 登录管理员账号，查看过去 30 天的问答量趋势图和热门问题 Top 10 列表，验证数据与实际问答记录一致。

**Acceptance Scenarios**:

1. **Given** 系统已累积 30 天问答数据, **When** 管理员进入统计页面, **Then** 展示每日问答量折线图、准确率趋势（基于 Faithfulness 评分），热门问题 Top 10 列表可点击查看详情。
2. **Given** 无统计数据, **When** 用户首次进入统计页面, **Then** 显示空状态引导（"暂无数据，开始使用问答功能后即可查看统计"），无空白页面。
3. **Given** 管理员选择特定时间范围, **When** 切换时间筛选器, **Then** 图表和列表实时更新为所选时间范围的数据。

---

### User Story 5 - 外部系统集成 API (Priority: P2)

OA 系统或其他内部系统通过 RESTful API 调用问答服务，API 网关提供 JWT 认证、RBAC 鉴权、OpenAPI 文档，为后续系统集成预留标准接口。

**Why this priority**: API 网关是产品走向集成的必要条件，但 M5 阶段优先完成 Web 界面用户体验。API 网关与 Web 界面共享认证和权限底层，开发顺序可并行。

**Independent Test**: 使用管理员创建的 API Token 调用 /api/v1/qa/ask 接口，验证返回结构化问答结果；使用无权限 Token 调用，验证返回 403。

**Acceptance Scenarios**:

1. **Given** 有效 JWT Token, **When** 调用 /api/v1/qa/ask 接口提交问题, **Then** 返回包含回答、引用来源、置信度的结构化 JSON 响应。
2. **Given** 无效或过期 JWT Token, **When** 调用任何 API 接口, **Then** 返回 401 Unauthorized，不泄露内部信息。
3. **Given** 普通用户角色的 JWT Token, **When** 调用文档管理 API, **Then** 返回 403 Forbidden，操作被拒绝。

---

### Edge Cases

- 用户会话超时后再次提问，系统应提示重新登录，不丢失未完成的问答记录。
- 管理员上传超大文件（>100MB）或格式损坏文件，系统应在前端提示文件限制，后端拒绝并返回明确错误信息。
- 流式回答过程中网络中断，已展示的内容应保留，中断位置可重试或显示"连接中断"提示。
- 并发用户同时操作同一文档（如一个删除、一个更新分类），系统应返回冲突提示，不静默覆盖。
- 标准答案别名与标准问题文本重复时，系统应提示冲突，不静默创建可能引起 Early Exit 歧义的条目。

## Requirements *(mandatory)*

### Functional Requirements

**问答界面**

- **FR-001**: 系统 MUST 提供 Web 问答页面，支持用户输入自然语言问题并获取回答。
- **FR-002**: 系统 MUST 以流式方式展示 LLM 生成内容（打字机效果），首字符延迟 < 1.5 秒。
- **FR-003**: 系统 MUST 在回答文本中以可交互标注形式嵌入引用来源，点击标注可展开原文片段。
- **FR-004**: 系统 MUST 保留会话历史，支持用户在同一会话中追问（基于 M4 多轮对话能力）。
- **FR-005**: 系统 MUST 在命中标准答案时即时展示（无流式效果），并标注"标准答案"标签。

**管理后台 - 文档管理**

- **FR-006**: 系统 MUST 提供文档上传界面，支持 PDF、Word、Markdown、HTML 四种格式，并在上传时指定元数据（来源、类别、版本、生效日期）。
- **FR-007**: 系统 MUST 实时展示文档索引状态（排队中/处理中/完成/失败），处理中的文档显示进度百分比。
- **FR-008**: 系统 MUST 支持文档的软删除和批量操作（批量删除、批量添加分类标签）。
- **FR-009**: 系统 MUST 展示知识库概览（文档总数、按类别分布、最近更新时间、索引存储大小）。

**管理后台 - 标准答案管理**

- **FR-010**: 系统 MUST 提供标准问答对的 CRUD 界面，支持编辑问题、答案、别名列表、生效/过期日期。
- **FR-011**: 系统 MUST 在创建或编辑标准答案时校验唯一性（问题文本和别名不与已有条目重复）。
- **FR-012**: 系统 MUST 展示标准答案的有效期状态（生效中/即将过期/已过期），并提供批量状态变更操作。

**管理后台 - 审核工作流**

- **FR-013**: 系统 MUST 提供审核队列界面，展示待审核的候选问答对（M2 Early Exit 产生）。
- **FR-014**: 系统 MUST 支持审核操作：确认（转入标准答案）、驳回（标注原因）、修改后确认。
- **FR-015**: 系统 MUST 提供审核统计看板：待审核数量、已确认/驳回数量、审核者贡献排名。

**管理后台 - 使用统计**

- **FR-016**: 系统 MUST 提供问答量趋势图（按日/周/月粒度）。
- **FR-017**: 系统 MUST 提供回答准确率趋势图（基于 M2 Faithfulness Evaluator 评分）。
- **FR-018**: 系统 MUST 提供热门问题排名列表（Top N），支持点击查看问题详情和引用来源。
- **FR-019**: 系统 MUST 在统计页面无数据时展示空状态引导，不显示空白页面。

**API 网关**

- **FR-020**: 系统 MUST 提供 RESTful API 接口，覆盖问答、文档管理、标准答案管理、审核操作，并自动生成 OpenAPI 文档。
- **FR-021**: 系统 MUST 对所有 API 请求进行 JWT Token 认证，Token 过期返回 401。
- **FR-022**: 系统 MUST 对所有 API 请求进行 RBAC 鉴权，越权操作返回 403。
- **FR-023**: 系统 MUST 对流式问答 API 提供 Server-Sent Events (SSE) 响应，支持增量输出。
- **FR-024**: 系统 MUST 为后期 OA 系统集成预留 SSO 认证接口（仅预留，不在 M5 实现）。

**RBAC 权限控制**

- **FR-025**: 系统 MUST 定义三种角色：管理员（全权限）、业务专家（标准答案管理+审核标注）、普通用户（仅问答）。
- **FR-026**: 系统 MUST 按文档分类标签限制普通用户的访问范围（如仅能查询"清算规则"类文档）。
- **FR-027**: 系统 MUST 记录所有管理操作的审计日志（谁在何时做了什么），存储于 M4 审计日志体系。
- **FR-028**: 系统 MUST 在 Web 界面中根据用户角色隐藏或禁用无权限的操作入口。

### Key Entities

- **User**: 系统用户。属性：用户名、角色（管理员/业务专家/普通用户）、可访问的分类标签集、创建时间。
- **Session**: 用户问答会话。属性：会话 ID、用户 ID、创建时间、消息列表。复用 M4 多轮对话实体。
- **DocumentRecord**: 知识库文档记录。属性：文件名、格式、元数据（来源/类别/版本/生效日期）、索引状态、上传者 ID、上传时间。
- **StandardAnswer**: 标准问答对。属性：问题文本、答案文本、别名列表、生效日期、过期日期、状态、创建者 ID。扩展 M3 实体。
- **ReviewItem**: 审核队列表项。属性：候选问题、候选答案、来源（Early Exit 触发）、状态（待审核/已确认/已驳回）、审核者 ID、审核时间、驳回原因。复用 M3 实体。
- **APIKey**: API 访问凭据。属性：Token 值、关联用户 ID、权限范围、创建时间、过期时间、是否启用。新增实体。
- **AuditLogEntry**: 审计日志条目。属性：操作者 ID、操作类型、目标实体、操作时间、操作详情。复用 M4 实体。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 问答页面首屏渲染时间 < 1.5 秒（含静态资源加载）。
- **SC-002**: 问答流式输出首字符延迟 < 2 秒（含 LLM 首 Token 时间）。
- **SC-003**: 用户操作反馈（按钮点击、表单提交）< 100ms（界面响应，不含后端处理）。
- **SC-004**: 文档上传到索引状态更新延迟 < 3 秒（状态轮询或推送）。
- **SC-005**: 所有 API 端点的 OpenAPI 文档完整率 100%，请求/响应模型均含示例。
- **SC-006**: JWT 认鉴权覆盖率 100%（所有 API 端点均需有效 Token 且角色匹配）。
- **SC-007**: RBAC 权限边界零泄漏：普通用户无法访问文档管理 API，业务专家无法访问用户管理 API。
- **SC-008**: 审核统计看板数据与审核记录一致率 100%（看板数字 = 实际记录数）。
- **SC-009**: 前端测试覆盖率 ≥ 80%（单元 + 集成），后端 API 测试覆盖率 ≥ 80%。
- **SC-010**: 所有用户界面空状态有明确引导文案和操作提示，无空白页面。

## Assumptions

- M1-M4 全部能力已就绪且可被 Web 层和 API 层调用（Haystack Pipeline、混合检索、标准答案、多轮对话、审计日志、OTel 均已可用）。
- 后端技术栈为 Python FastAPI + Haystack 2.x，前端为 React + Ant Design + Vite，spec 不限定实现但确认技术约束。
- 用户数据（账号、角色、权限）存储于 PostgreSQL，会话状态可缓存于 Redis。
- JWT 为 M5 唯一认证方式，SSO 仅预留接口不在 M5 实现。
- 部署方式为 Docker Compose + systemd，spec 不限定容器编排细节。
- 前端构建产物为静态文件，由 FastAPI 或独立 Nginx 托管（实现阶段确定）。
- API 版本从 v1 开始，路径前缀 /api/v1/，破坏性变更通过版本升级管理。
- 统计数据来源于 M4 审计日志和 M2 Faithfulness Evaluator 评分记录。
- Web 界面仅支持桌面浏览器（Chrome、Firefox、Edge 最新两个主版本），移动端适配不在 M5 范围。
- 国际化不在 M5 范围，界面语言为中文简体。
- M5 交付即产品最终形态，需可通过最终验收测试。
- 性能指标（首屏 < 1.5s、操作反馈 < 100ms）基于本地部署环境（LAN 网络延迟 < 10ms）。
